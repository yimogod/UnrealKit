# 架构与分层约定

本文定义 UnrealKit 的分层边界、依赖方向和跨层协作契约。任何新增功能都必须先确认它属于哪一层。

## 技术基线

| 项 | 取值 | 来源 |
| --- | --- | --- |
| 目标框架 | `net9.0`（Core/Cli）、`net9.0-windows`（Desktop/Tests） | 各 `.csproj` |
| 语言版本 | `latest` | `UnrealKit/Directory.Build.props` |
| 可空引用 | `enable` | `Directory.Build.props` |
| 隐式 using | `enable` | `Directory.Build.props` |
| 警告即错误 | `TreatWarningsAsErrors=true` | `Directory.Build.props` |
| 代码风格检查 | `EnforceCodeStyleInBuild=true` | `Directory.Build.props` |
| GUI 框架 | WPF（Windows 平台） | `UnrealKit.Desktop` |
| 第三方依赖 | ClosedXML 0.104.2（真实 XLSX 写出） | `UnrealKit.Core.csproj` |

警告即错误意味着未使用的变量、可空性告警和风格问题都会中断构建。提交前必须构建通过，不要用 `#pragma warning disable` 掩盖问题。

## 解决方案结构

```text
UnrealKit/
├─ Directory.Build.props   # 全解决方案共享的编译属性
├─ UnrealKit.Core/         # 领域模型、配置、ADB、采集、解析、分析、导出
│  ├─ Adb/                 # 设备枚举、Wi-Fi 连接、adb 路径解析
│  ├─ Analysis/            # 基线差分（跨报告类型的指标比较）
│  ├─ Capture/             # 采集编排、归档、Manifest、采集分析
│  ├─ Diagnostics/         # Diagnostic 记录与严重级别
│  ├─ Export/              # CSV/TSV/XLSX 导出服务
│  ├─ Launch/              # uecommandline.txt 启动参数与预设
│  ├─ Operations/          # 进度、日志事件、IOperationLogger
│  ├─ Parsing/             # meminfo / memreport / 静态相机解析器
│  ├─ Processes/           # 参数化外部进程执行
│  ├─ Projects/            # .ukit 描述符、INI 读写、工程服务
│  └─ Runtime/             # 版本信息与应用路径
├─ UnrealKit.Cli/          # 命令解析、控制台呈现、退出码
├─ UnrealKit.Desktop/      # WPF 视图与 ShellViewModel
├─ UnrealKit.Tests/        # 单元测试、金样测试、TestData 样本
└─ Output/                 # 集中式构建输出（已在 .gitignore 中忽略）
   ├─ Bin/<项目>/<配置>/<框架>/
   └─ Obj/<项目>/<配置>/<框架>/
```

## 构建输出目录

各项目不再在自身目录下生成 `bin/` 和 `obj/`，而是通过 `Directory.Build.props` 的
`BaseOutputPath` / `BaseIntermediateOutputPath` 统一收敛到 `UnrealKit/Output/` 下：

```text
UnrealKit/Output/Bin/UnrealKit.Cli/Debug/net9.0/UnrealKit.Cli.exe
UnrealKit/Output/Bin/UnrealKit.Desktop/Release/net9.0-windows/UnrealKit.Desktop.exe
```

WPF 在编译 XAML 时会生成形如 `UnrealKit.Desktop_xxxxxxxx_wpftmp` 的临时工程，
`Directory.Build.props` 会剥掉该后缀，使临时工程与主工程共用同一中间目录，
避免在 `Output/Obj` 下堆积一次性目录。

`Directory.Build.props` 同时把 `bin\**` 和 `obj\**` 追加到 `DefaultItemExcludes`。
SDK 只会把当前配置的输出路径排除在源文件 glob 之外，输出路径改到 `Output\` 后，
项目内遗留的 `obj\` 会被当作源码编译，产生 `CS0579` 特性重复错误。这条排除保证
旧目录或被外部工具重建的目录不会破坏构建，修改输出路径相关属性时不要移除它。

引用输出路径的脚本（`Script/Run-*.bat`）必须使用上述路径；新增脚本时不要拼回旧的
`<项目>/bin/<配置>` 形式。`Script/Publish-Shipping.bat` 通过 `--output` 显式指定发布目录，
不受此设置影响。

依赖方向严格单向：`Cli → Core`、`Desktop → Core`、`Tests → Core + Desktop`。

## 各层职责

### UnrealKit.Core

承载全部业务规则，是唯一允许实现采集、解析、导出逻辑的地方。

- 不得引用 WPF、`System.Windows.*`、命令行框架或任何视图类型。
- 不得直接读写控制台，也不得弹出对话框；通过返回值、`Diagnostic` 和 `IProgress<T>` 表达结果。
- 长耗时操作暴露为异步 API，并接受 `CancellationToken`。
- 外部服务（模型提供方、RenderDoc 等）必须通过 Core 定义的接口接入，Core 不依赖具体 SDK。

### UnrealKit.Cli

只做参数绑定、输出格式化和退出码，不承载业务规则。命令约定见 `Doc/CLI约定.md`。

### UnrealKit.Desktop

只负责交互、展示、进度反馈和用户确认。

- 不拼接 ADB 命令，不解析文本，不自行组织归档目录。
- 业务流程写在 `ShellViewModel` 或 Core 服务中，不写在 code-behind；`ShellViewModel` 必须可在无 UI 环境下被测试（现有 `DesktopShellViewModelTests` 依赖这一点）。
- 导航为 11 页，按依赖顺序分 4 组：

  | 分组 | 页面 | 前提 |
  | --- | --- | --- |
  | 工程 | 工程、工程配置 | 无 |
  | 设备与运行 | 设备、启动参数、控制台 | 已打开工程 |
  | 采集 | 采集归档、RenderDoc | 已明确选择设备 |
  | 分析 | 内存解析、静态相机、基线差分、历史趋势 | 已有输入文件或归档 |

  「内存解析」页内再分四个分页：Android meminfo、UE memreport、导出、归档浏览。导出格式由输出扩展名决定（`.xlsx` 真实工作簿、`.tsv` 制表符文本），因此输出路径只经保存对话框选取，不让用户手打扩展名。

  导航由 `MainWindow.xaml` 的 `TabControl` 声明，但**必须由 `ItemsSource` 驱动**（页面清单为资源 `NavigationPages`，经 `NavigationPagesView` 按 `Group` 分组）：写字面 `TabItem` 子元素时 `Items.CanGroup` 恒为 `false`，`GroupDescriptions` 会被静默忽略、分组标签不渲染。同理，内容宿主绑定 `SelectedItem.View` 而非 `ContentSource="SelectedContent"`——后者在非 `TabItem` 项上恒为 `null`。`NavigationPage.Title` 即页面标识，通过 `SelectedValuePath="Title"` 双向绑定 `SelectedNavigationItem`。新增页面时追加 `NavigationPage` 与 `PageDescription` 分支。
- 操作日志是全局的，不属于任何页面：统一写入 `ShellViewModel.OperationLogs`（`OperationLogEntry` 记录时间戳、分类、正文），由品牌栏的「操作日志」按钮打开独立的 `Views/OperationLogWindow`（单实例，带清空与保存）。新增日志调用 `AddOperationLog(category, message)`，**不要自带时间前缀**——时间戳在该方法内统一生成。页面内只显示当前阶段（`OperationStage`），不再自建日志列表。
- 不得阻塞 UI 线程；所有 ADB、I/O、导出调用使用 `await`。
- 字号、字重、弱化文字颜色不写在控件上，统一引用 `Styles/Typography.xaml`（由 `App.xaml` 合并）中的具名样式。字号阶梯与样式用途见下表；新增页面直接复用，需要新层级时先在字典中补样式，不在视图里写字面值。

| 样式 | 用途 |
| --- | --- |
| `AppTitleTextStyle` | 品牌栏应用名（22） |
| `PageHeaderTextStyle` | 导航模板注入的页面标题（20） |
| `SectionTitleTextStyle` | 页内区块标题（18） |
| `ResultSummaryTextStyle` | 结果区顶部摘要（16，绑定内容，允许换行） |
| `SectionDescriptionTextStyle` | 区块标题下的说明段落 |
| `FieldLabelTextStyle` / `StackedFieldLabelTextStyle` | 表单字段标签；后者用于竖排表单第二项起，与上一字段留出间距 |
| `EmphasisTextStyle` | 仅加粗，间距由外层容器决定 |
| `HintTextStyle` | 次要说明、状态提示（弱化色 `#FF52616B`） |
| `NavigationGroupLabelTextStyle` | 左侧导航分组标签 |
| `MonospaceOutputTextBoxStyle` / `ConsoleEchoTextBoxStyle` | 只读等宽输出框；后者为浅灰底无边框的控制台回显 |

文本样式一律以 `x:Key` 显式引用，不使用隐式 `TargetType` 样式：隐式样式会顺着资源查找链污染 `DataGrid` 单元格、按钮文本和 `TabItem` 标题，理由同 `MainWindow.xaml` 中导航样式的说明。

### UnrealKit.Tests

覆盖 Core 与 ShellViewModel。约定见 `Doc/测试与质量约定.md`。

## 跨层协作契约

### 诊断

`UnrealKit.Core.Diagnostics.Diagnostic` 是解析、校验和采集问题的统一表达：

```csharp
public sealed record Diagnostic(
    DiagnosticSeverity Severity,   // Information | Warning | Error
    string Code,                   // 稳定标识，见 Doc/解析导出与诊断.md
    string Message,
    string? Path = null,
    string? SuggestedFix = null,
    int? LineNumber = null);
```

- 服务返回诊断集合，由 CLI/GUI 决定如何呈现，Core 不负责措辞排版。
- 校验结果以「是否含 Error」判断成败，参考 `ProjectValidationResult.IsValid`。
- 已发布的 `Code` 视为公开契约，不得复用或改变语义。

### 进度与日志

`UnrealKit.Core.Operations` 提供跨层的进度与日志载体：

- `OperationProgress(OperationId, Stage, CurrentItem, TotalItems, Message, Error)` 用于向 UI 汇报阶段与计数。
- `LogEvent(Timestamp, Level, OperationId, Message, Properties, Exception)` 与 `IOperationLogger` 用于结构化日志；不需要日志的调用方使用 `NullOperationLogger.Instance`。
- 每个可取消的长流程应有稳定的 `OperationId`，便于 GUI 关联进度、日志和取消。

### 外部进程

所有外部命令统一经 `UnrealKit.Core.Processes.ProcessRunner` 执行，它提供参数化调用、超时、取消、进程树终止和逐行流式输出。安全要求见 `Doc/设备操作与文件安全.md`。

## 代码风格

- 优先强类型 `record` 模型，不在业务层传递无结构字典或制表符字符串。
- 公共 API、配置字段、用户可见错误和导出列名使用清晰稳定的命名；重命名等同破坏性变更。
- 保持改动小而聚焦；不顺手重构与当前任务无关的代码。
- 新增依赖必须说明用途，优先选择维护活跃、许可兼容的库。
- Core 诊断与导出列名使用英文；GUI 文案与面向中文用户的错误提示使用中文。修改时与所在文件保持一致，不要混用。
- 批处理脚本使用原生 bat 语法，不使用 PowerShell 语法。
