# 解析、导出与诊断

## 解析原则

旧 Python 解析器依赖固定文本标签和行格式，缺失时静默以零值替代。新解析器必须相反：

- 失败时给出具体的缺失段落、行号或格式原因，不静默补零。
- 部分解析成功时返回已解析数据 + Warning 级诊断，让调用方判断可用性。
- 保留原始行与行号，便于从结论回溯到输入文件的具体位置。
- 对同目录下的多份 `meminfo_*.txt` 或 `.memreport`，列出候选文件信息由调用方明确选择，不取「第一份」。
- 解析阶段不修改输入文件。

## 诊断码

`Diagnostic.Code` 是稳定契约，按前缀分域：

| 前缀 | 域 | 当前范围 |
| --- | --- | --- |
| `UKIT` | 工程创建、打开、校验 | `UKIT001`–`UKIT007` |
| `AMI` | Android meminfo 解析 | `AMI101`–`AMI107`、`AMI201`–`AMI203`、`AMI210`–`AMI213`、`AMI220`–`AMI223` |
| `UMR` | UE memreport 解析 | `UMR101`、`UMR201`–`UMR202`、`UMR301`–`UMR306` |
| `SCP` | 静态相机性能日志解析 | `SCP100`–`SCP104`、`SCP201`–`SCP204`、`SCP206` |
| `WMI` | Win64 进程内存计数器解析 | `WMI100`–`WMI101`、`WMI103` |
| `BDF` | 基线差分 | `BDF101`–`BDF103`、`BDF201`–`BDF203` |
| `TRD` | 历史趋势 | `TRD101`–`TRD105`、`TRD201`–`TRD204` |

编号习惯：`x0x` 为必需内容缺失，`x2x` 为重复或数值非法，`x3x` 为明细区段问题。新增码在对应域内向后追加，不复用已发布编号，不改变既有编号的含义。

## 解析器现状

### AndroidMemInfoParser

覆盖 App Summary、Detailed PSS、Dalvik、Objects 区段，并兼容 OEM 定制的列顺序与额外列变体。

### UnrealMemReportParser

- 摘要指标：Changelist、Wwise、Lua、Texture Streaming、Shader、RHI、LLM；内存值统一换算为 KiB。
- 明细：纹理（尺寸、像素格式、内存）、Render Target、对象（类名、数量、内存）。
- 缺少 `Changelist:` 返回 `UMR101` Error，因为无法确定构建版本的报告不可用于对比分析。

### Win64MemInfoParser

- 输入是 `Win64DeviceService.CaptureMemoryAsync` 产出的进程计数器文本，不是 Android 的 `dumpsys meminfo`；两者格式不同，不可互相解析。
- 缺少 `** WIN64 MEMINFO for process <name> (PID: <number>) **` 头返回 `WMI100` Error；头存在但格式错误返回 `WMI101` Error。
- 单个计数器数值无法解析返回 `WMI103` Warning，该计数器留空，其余计数器照常解析。`N/A` 是合法取值，表示该计数器不可用，留空且不产生诊断。
- 内存计数器在文本中以 MB 记录，解析后统一换算为字节存入 `Win64MemInfoCounters`。
- 计数器行按 `键: 值` 匹配，值使用懒惰量词以吸收行尾 CR，保证 CRLF 与 LF 输入解析结果一致。

### StaticCameraPerfParser

标签与阈值全部集中在 `StaticCameraPerfConfig`，不散落硬编码在解析器中：

- 区段标记：`!!!Do Perf Start!!!`、`!!!Do Perf End!!!`、`PointNum:`、相机信息起止标记。
- 指标标签：`frame`、`game`、`draw`、`rhi`、`gpu`、`mem`、`dc`、`prim`。
- 结构参数：`FramesPerCamera = 14`、`ScreenshotsPerCamera = 11`。
- 阈值：`FrameTimeWarningMs = 30.0` / `FrameTimeErrorMs = 33.4`、`DrawCallWarning = 400` / `DrawCallError = 500`、`TriangleWarning = 500000` / `TriangleError = 700000`。
- 设备信息标记：`LogInit: OS: `、`SRC_DeviceMake: `、`[SRC_GpuVendor]:`、`SRC_VulkanAvailable:`、`SRC_VulkanVersion:`。

`Config.Validate()` 强制 error 阈值严格大于 warning 阈值。旧脚本中 DC warning/error 同为 `500` 是已知缺陷，已修正为 `400/500`，不得回退。

截图与相机记录匹配前必须校验数量和顺序，不匹配时产生可见诊断而非静默对齐。

## 导出约定

- `.xlsx` 扩展名只能用于真实 XLSX 工作簿（经 ClosedXML 写出）；制表符文本使用 `.tsv` 或 `.txt`，逗号分隔使用 `.csv`。
- 导出结果必须保存输入来源、解析时间、工具版本和关键配置，确保可追溯。XLSX 通过独立的 `Metadata` 工作表承载。
- 导出列名视为公开契约；重命名或调整列序等同破坏性变更，需在 `CHANGELOG.md` 中说明。
- 诊断随导出一起输出（XLSX 的 `Diagnostics` 表 / CSV-TSV 的诊断区段），使导出结果自带可信度信息。

现有 XLSX 工作表结构：

| 服务 | 工作表 |
| --- | --- |
| `XlsxMemInfoExportService` | Metadata、AndroidMemInfo、PSS Details、Dalvik、Objects、Diagnostics |
| `XlsxMemReportExportService` | Metadata、MemReport Summary、Textures、Render Targets、Objects、Diagnostics |
| `XlsxTrendExportService` | Metadata、Trend Captures、Trend Series、Trend Points、Diagnostics |

`--include-details` 控制是否输出明细表；摘要模式必须独立可用。

## 差分与趋势

差分（P2）实现于 `UnrealKit.Core.Analysis.BaselineService`，趋势（P3）实现于 `UnrealKit.Core.Analysis.TrendService`。共同约束：

- 明确区分「基线」和「当前」，不使用「旧/新」等含义模糊的措辞。
- 标注单位、正负方向（增长是变差还是变好）和缺失项。
- 一侧缺失指标时输出「缺失」而非 `0`，避免把缺数据读成归零。

### BaselineService

同类报告的两侧比较，输入只读，不写回任何一侧。

- 支持四种来源：`MemInfo`、`Win64MemInfo`、`MemReport`、`StaticCamera`。来源由调用方显式指定，不从扩展名推断；跨来源比较返回 `BDF101` Error。CLI 取值分别为 `meminfo`、`win64-meminfo`、`memreport`、`static-camera`。
- `Win64MemInfo` 的指标组为 `ProcessMemory`，内存计数器单位为字节（`LowerIsBetter`），`ThreadCount` / `HandleCount` 为 `Neutral`。
- 任一侧解析失败（含 Error 级诊断）返回 `BDF102` / `BDF103` Error 且不产出任何指标，避免基于半份数据得出结论。两侧的原始解析诊断都会带 `[baseline]` / `[current]` 前缀透传。
- 指标键为 `Group/Name`。指标顺序以基线为准，仅出现在当前报告中的指标追加在末尾，不被丢弃。
- `MetricDirection` 标注方向：`LowerIsBetter`（内存、耗时、DrawCall、三角形数）、`HigherIsBetter`、`Neutral`（明细计数等无优劣含义的指标）。`Neutral` 指标变化记为 `Changed`，不记为回退或改善。
- `MetricDiffStatus` 区分四态：`Compared`、`MissingInBaseline`、`MissingInCurrent`、`MissingInBoth`。任一缺失态产生 `BDF202` Warning，`Delta` 与 `DeltaPercent` 均为 `null`。
- `DeltaPercent` 以基线绝对值为分母；基线为 `0` 时为 `null`，不产生无穷大。
- memreport 的 `Missing` / `Invalid` 摘要指标保留为 `null` 值的指标行，保持可见而不是从比较中消失。
- 静态相机按相机名而非索引对齐，相机重命名或顺序变化时两侧各自报缺失，不会错位比较。
- 指标过滤接受裸名或 `Group/Name`；未命中的名字产生 `BDF201` Warning，无可比指标时产生 `BDF203` Warning。这些都不影响成败判定。

### TrendService

按时间聚合多次采集的指标序列，复用 `MetricSample` 与 `MetricDirection`，只读 `Content/` 归档。

- 采集按日期升序排列（同日按 Capture ID 排序），差分是两点比较，趋势是同一套指标沿时间的序列。
- 指标顺序取首次出现顺序：最早一次采集的布局在前，后来新增的指标追加在末尾而不被丢弃。
- 单点缺失记为 `Value = null`，不补零。`TrendPoint.DeltaFromPrevious` 从**上一个有值的点**起算，中间的空档不会被读成「掉到零又回来」。
- 序列级 `TotalDelta` / `TotalDeltaPercent` 取首末两个有值点；有值点不足两个时为 `null`，`OverallAssessment` 为 `Unknown`。首值为 `0` 时百分比为 `null`。
- 排除单次采集的情形都产生具体诊断，不静默跳过：`TRD101` 指定文件不存在、`TRD102` 无对应类别文件、`TRD103` 同类文件不唯一、`TRD104` 缺少 manifest（设备过滤时）、`TRD105` manifest 不可读、`TRD202` 该次采集解析失败。
- 一次采集解析失败只排除该点，不使整个区间失败；其原始解析诊断以 Warning 级透传并带 `[CaptureId]` 前缀。
- `TRD201` 过滤未命中、`TRD203` 无采集匹配、`TRD204` 指标存在缺失点，均为 Warning。

趋势导出工作表结构：

| 服务 | 工作表 |
| --- | --- |
| `XlsxTrendExportService` | Metadata、Trend Captures、Trend Series、Trend Points、Diagnostics |

`--include-points` 控制是否输出 `Trend Points`；摘要（`Trend Series`）必须独立可用。缺失值在 CSV/TSV 与 XLSX 中都写为显式的 `missing`，不写 `0`，也不留空。
