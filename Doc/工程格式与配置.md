# `.ukit` 工程格式与配置

UnrealKit 使用 UE 风格的分析工程组织采集数据和配置。本文定义工程格式、目录职责和配置优先级。

## 工程描述符

工程描述文件扩展名为 `.ukit`，内容是 UTF-8 INI 文本，不是二进制格式。它保持小而稳定，仅描述工程身份和根目录约定。

```ini
[UnrealKit.Project]
FormatVersion=1
ProjectName=ExamplePerformance
ContentRoot=Content
ConfigRoot=Config
SavedRoot=Saved
IntermediateRoot=Intermediate
```

对应模型为 `UnrealKit.Core.Projects.UkitProjectDescriptor`，当前 `CurrentFormatVersion = 1`。新增可调业务配置时优先放入 `Config/DefaultGame.ini`，不要无限扩展 `.ukit`。

## 目录约定

```text
<ProjectRoot>/
├─ <ProjectName>.ukit          # 必需：工程描述符、格式版本、根目录约定
├─ Config/                     # 可选：UE 风格的可版本化默认配置
│  ├─ DefaultGame.ini          # 采集、路径、阈值和分析默认值
│  └─ UserSetting.ini          # 个人界面状态（平台作用域），建议在版本控制中忽略
├─ Content/                    # 受工程管理的原始采集数据；不修改原件
│  └─ <Platform>/<Tag>/<YYYY-MM-DD>/<CaptureId>/
│     ├─ CaptureManifest.json  # 来源、设备、时间、文件清单、校验信息
│     ├─ MemInfo/
│     ├─ Saved/
│     ├─ Logs/
│     ├─ Screenshots/
│     ├─ Profiling/
│     └─ GPUDumps/
├─ Saved/                      # 可重新生成的派生数据
│  ├─ Exports/
│  ├─ Analysis/
│  ├─ Reports/
│  └─ Logs/
└─ Intermediate/               # 可删除的缓存、解压和临时处理文件
```

- `Content/` 是采集数据的权威存档。导入、拉取或解析时不得修改其中的原始文件。
- `Platform` 例如 `Android`；`Tag` 是用户定义的场景、版本、测试批次或性能标签；日期必须使用 ISO 格式 `YYYY-MM-DD`。
- `CaptureId` 必须唯一，建议 `yyyyMMdd-HHmmss` 加设备或随机后缀，避免同日多次采集冲突。
- `Saved/`、`Intermediate/` 是派生或可再生数据；清理它们不得删除 `Content/` 中的原始采集数据。
- 创建工程时只生成必要的空目录和 `.ukit`/默认配置，不创建虚假的采集数据。

`UkitProject` 通过描述符中的根目录名派生实际路径（`ContentDir`、`ConfigDir`、`SavedDir`、`IntermediateDir`、`ConfigFilePath`），代码中不要硬编码 `"Content"` 等字面量。

## 项目配置

`Config/DefaultGame.ini` 是可选的项目默认配置，采用 UE 工程师熟悉的命名。节名使用 `[/Script/UnrealKit.*]` 或 `[UnrealKit.*]`，字段保持稳定、可读、可手动编辑。

`ProjectSettings` 的跨平台配置项：

| 字段 | 用途 | 默认值 |
| --- | --- | --- |
| `SettingsVersion` | 配置布局版本，当前为 `2` | `2` |
| `UnrealProjectName` | UE 工程名 | 工程名 |
| `LocalWorkingDirectory` | 本地工作目录 | 空 |
| `RemoteControlHttpPort` | Remote Control HTTP 端口 | `30010` |
| `RemoteControlObjectPath` | Remote Control 可调用对象路径 | `/Script/Engine.Default__KismetSystemLibrary` |
| `RemoteControlFunctionName` | Remote Control 函数名 | `ExecuteConsoleCommand` |
| `RemoteControlCommandParameter` | 控制台指令参数名 | `Command` |
| `DefaultCaptureTag` | 默认采集标签 | `Default` |
| `DefaultExportDirectory` | 默认导出目录 | `Saved/Exports` |
| `LaunchParameterPresets` | 启动参数预设 | 见下 |

## 设备别名

设备列表默认只显示设备 id（Android 为 ADB 序列号，Win64 为 `localhost`）和设备自报的型号。同型号的多台测试机在列表里无从区分，因此可以在 `[UnrealKit.DeviceAliases]` 下给设备 id 配一个人类可读的别名：

```ini
[UnrealKit.DeviceAliases]
6d062c71=小米平板5-测试机A
192.168.1.100:5555=测试机B-无线
localhost=我的开发机
```

- 键是设备 id，与 `IDevice.Id`、CLI 的 `--device` 取同一个值，因此别名在任何列出设备的地方都能按 id 查到，不需要额外一次设备查询。ADB 序列号大小写不敏感，别名查找与 `--device` 匹配保持一致。
- Wi-Fi 连接的设备 id 形如 `ip:port`，会随网络变化；这类条目要按当前 id 维护，或改用 USB 序列号。
- **别名只用于辨认设备，不参与设备选择。** 采集、启动、指令仍以设备 id 为准，日志与归档记录的也是 id。让别名可用于选择设备，等于把「同一别名配到两台设备」变成一次隐式选择。
- 配了别名的设备在列表里多显示一列别名；没配的那一列留空，不回填 id 或型号——占位内容会让「没配别名」看起来像别名就叫这个。
- 别名走分层合并：`BaseGame.ini` 可提供团队共用的设备别名，工程的 `DefaultGame.ini` 覆盖同一 id。
- 别名是可选的附加信息：未打开工程或未配置别名时设备列表照常可用。

对应模型是 `DeviceAliasMap`（`ProjectSettings.DeviceAliases`），展示投影是 `UnrealKit.Core.Devices.DeviceDisplayInfo`。别名解析放在 Core，GUI 与 CLI 共用同一套规则，避免两处对「有别名显示别名、没有则显示型号」的处理分叉后同一台设备在两个界面里名字不同。`DeviceDisplayInfo` 刻意不实现 `IDevice`：它是展示投影，让它冒充设备会让采集、指令等操作接受一个展示对象而绕过设备枚举得到的真实状态；操作一律传 `DeviceDisplayInfo.Device`。

## 平台配置

**同一工程可以同时配置多个平台，平台之间不互斥。** 一个 UE 工程在 Android、Win64 上都跑是常态，因此配置里没有「当前平台」字段——本次操作打哪个平台由所选设备决定（CLI 用 `--device` / `--platform`，GUI 用设备列表），属于会话选择，不写进版本化的工程配置。

每个平台一个 INI 节，节名为 `[UnrealKit.Platform.<平台名>]`。**只有工程自己的 `Config/DefaultGame.ini` 中出现的平台节才算「已配置」**；`BaseGame.ini` 中的同名节只提供字段默认值（例如组织级 `AdbPath`），不会让每个工程都看起来支持全部平台。

`[UnrealKit.Platform.Android]`：

| 字段 | 用途 | 默认值 |
| --- | --- | --- |
| `PackageName` | Android 包名 | 空（需用户填写） |
| `Activity` | 启动 Activity | 空 |
| `GameRootTemplate` | 设备端游戏根目录模板 | `/sdcard/Android/data/{PackageName}/files/UnrealGame/{UnrealProjectName}/{UnrealProjectName}` |
| `AdbPath` | 项目级 adb 路径 | 空 |
| `FtpPath` | 该平台在 FTP 服务器上的下载父目录 | 空 |

**Saved 目录不是配置项**：它固定是 Game 目录下的 `Saved` 子目录（`PlatformProfile.SavedDirectoryName`），由 `Resolve` 派生。UE 自身就是这个布局，两处分别配置只会让它们对不上，而错开的 Saved 路径会让采集在空目录上报告成功。Win64 侧一直是这个规则，Android 侧与之统一。

`[UnrealKit.Platform.Win64]`：

| 字段 | 用途 | 默认值 |
| --- | --- | --- |
| `Executable` | 可执行文件路径（绝对路径） | 空 |
| `WorkingDirectory` | 工作目录（绝对路径），用于定位 Saved 与 `uecommandline.txt` | 空 |
| `FtpPath` | 该平台在 FTP 服务器上的下载父目录 | 空 |

路径模板中的 `{PackageName}`、`{UnrealProjectName}` 由 `PlatformProfile.Resolve` 在运行时替换。新增占位符时同步更新对应 profile 与本表。

## FTP 下载配置

FTP 下载用于把最新构建拉取到本地：Android 下载最新子目录中的 `.apk`，Win64 下载整个最新子目录。**主机 / 端口 / 凭据跨平台共享**（一个 FTP 服务器），各平台的父目录分别配置在各自 profile 的 `FtpPath` 中。

`[UnrealKit.Ftp]`（`Config/DefaultGame.ini`）：

| 字段 | 用途 | 默认值 |
| --- | --- | --- |
| `Host` | FTP 服务器主机名或地址 | 空 |
| `Port` | FTP 端口，空回退 `21` | `21` |
| `Username` | 登录用户名 | 空 |
| `Password` | 登录密码（敏感信息） | 空 |

- `Host` 为空表示未启用 FTP 下载，进入网络前即报错并指名缺 `Host`；目标平台的 `FtpPath` 为空同样在下载前报错。
- 下载父目录下按目录名**自然排序**（数字段按数值、文本段不区分大小写逐段比较）取最大者作为「最新」子目录。无子目录、连不上、列目录失败、多个 apk、无 apk 分别以 `DWN001`–`DWN005` 诊断返回。
- 落地目录是 `Intermediate/Download/<Platform>/<子目录>/`：`Intermediate` 是可删除缓存，构建产物不写入 `Content/`，避免把下载的安装包误当采集归档。
- **`Password` 是敏感信息**：GUI 用 `PasswordBox` 掩码，日志与 CLI 输出不得打印明文。这属于用户明确要求的例外——按通用约定「不得在项目配置存储敏感信息」，若项目配置会被提交到公共仓库，请改用不含密码的共享主机或自行脱敏。

### 平台差异的唯一出口

`PlatformProfile`（`AndroidPlatformProfile` / `Win64PlatformProfile`）负责把配置解析成平台中立的 `PlatformTarget`，其中含进程标识、启动目标、已展开的设备端路径。**采集、启动参数投放、控制台指令等服务只消费 `PlatformTarget`，内部不得按平台分支**——那会让平台知识重新散布到各处，新增平台需要改动所有调用方。

- 新增平台：加 `TargetPlatform` 成员、一个 `PlatformProfile` 子类、`PlatformProfileIni` 中的读写映射、`ProjectSettings` 上的 profile 属性，以及一个 `IDeviceProvider`/`IDeviceService` 实现。调用方不改。
- 设备所在平台未配置时报错并列出已配置平台，不回退到其他平台的配置——用错误的路径采集会拉到空目录却报告成功。
- 平台字段留空可以保存（半成品配置），但执行操作时 `Resolve` 会要求必需项齐备并指名缺哪一项。

内置启动参数预设（`LaunchParameterPresetDefaults.All`）：`LLM`（`-llm`）、`LLM CSV`（`-llmcsv`）、`OpenGL`（`-OpenGLES`）、`Vulkan`（`-vulkan`）、`Trace Default`、`Trace All`、`Trace Network`、`Trace Memory`、`No Update`。预设只带名称、参数与描述，不带组合属性——组合约束由下面的分组表达，因此新增预设不必写死「是否可组合」，只需按需归组。Trace 与 No Update 系列的实际参数需在 `DefaultGame.ini` 中按工程配置。

### 启动参数预设分组

预设之间的互斥关系用「分组」表达，写在 `Config/DefaultGame.ini` 的 `[UnrealKit.LaunchPresetGroups]` 节。每个键是组名，值是 `模式:成员1,成员2`：

```ini
[UnrealKit.LaunchPresetGroups]
Render=Exclusive:Render.OpenGL,Render.Vulkan
Trace=Coexist:Trace.Client_All,Trace.Client_Default
```

- `Exclusive`（互斥组）：**组内最多选一个**；成员与组外预设可自由叠加。用于二选一的场景（如渲染后端 OpenGL / Vulkan）。
- `Coexist`（同组）：组内不施加约束，纯粹用于在界面给相关预设分组展示。
- 未归组的预设彼此可自由叠加。分组走分层合并：`BaseGame.ini` 提供组织级默认分组，`DefaultGame.ini` 覆盖同组名。
- 模式只能写 `Exclusive` / `Coexist`，写错或漏写冒号会报错——不静默当互斥处理，否则用户会以为约束生效实则没拦。
- 内置默认只有 `Render` 互斥组；`Mem.*`、`Trace.*`、`Profile.RemoteControl` 彼此与渲染后端正交，默认不归组。

## 界面状态

界面状态不是可版本化的工程配置，因此都不写进 `.ukit` 或 `Config/DefaultGame.ini`。按「它属于软件还是属于某个工程」分成两处：

### 软件级：`<程序目录>\Config\EditorSetting.ini`

| 节 | 键 | 用途 |
| --- | --- | --- |
| `UnrealKit.RecentProject` | `LastProjectFilePath` | 上次打开或创建的 `.ukit` 绝对路径，GUI 启动时据此恢复 |

由 `UnrealKit.Core.Runtime.IEditorSettingStore` 读写，路径来自 `ApplicationPaths.AppConfigDir`，与随程序分发的 `BaseGame.ini` 同级。「上次打开哪个工程」不能存在工程里——要先知道打开哪个工程，才能去读它的配置。

### 工程级：`<ProjectRoot>\Config\UserSetting.ini`

| 节 | 键 | 用途 |
| --- | --- | --- |
| `UnrealKit.Scope` | `Platform` | 该工程上次选择的平台作用域（平台名或 `All`），打开工程时据此恢复 |

由 `UnrealKit.Core.Runtime.IUserSettingStore` 读写，路径来自 `UkitProject.UserSettingFilePath`。作用域是「在这个工程里看哪个平台」，换工程就该换一份；记在软件级会让上一个工程的作用域跟到下一个工程，把另一个平台的设备与归档静默藏起来。它与 `DefaultGame.ini` 同目录但分文件：后者是可版本化的工程配置，不该因为「谁上次看的是哪个平台」产生 diff。

两个文件共用同一套读写规则（`IniStateFile`）：写入时保留文件中的其它节，删除文件只是丢失便利性，不影响任何工程数据。读不出来或取值无法识别都按「没有记录」处理——手工改坏状态文件不该让应用起不来。「没有记录」与「记录为 `All`」是两回事：前者保留当前作用域，把它当成后者会在打开工程时重置用户刚选的平台。

### 平台作用域

`PlatformScope` 表示「本次分析聚焦哪个平台」，约束 GUI 的设备列表、采集归档列表与历史趋势。

**它是视图过滤器，不是「当前平台」配置**，因此不在 `.ukit` 或 `DefaultGame.ini` 中占字段。`.ukit` v2 已移除 `Platform` 字段（见下方兼容性一节），操作用哪个平台始终由所选设备派生（`ProjectSettings.ResolveTarget`）。把平台重新变成配置状态会产生两个互相矛盾的真值来源：配置说 Win64、用户选中一台 Android 设备时，无论听谁的都是错的。

- `PlatformScope.All` 表示不过滤。没有「默认某个平台」的取值——隐式默认会让另一个平台的设备与归档静默消失。
- 作用域随工程记录，在工程打开后恢复；未打开工程时它只是本次会话的临时选择，无处可记也不落盘。
- 作用域收窄时设备枚举同步收窄，与 CLI 的 `--platform` 一致：聚焦 Win64 时不再为一个用不到的平台去起 adb。
- 已选设备落到作用域外时清空选择；仍在作用域内则保持。作用域内唯一可用设备仍会自动选中——作用域是用户的显式选择，其中唯一的设备不构成隐式选择。

## 配置优先级

优先级必须明确，并在 GUI/CLI 中可见：

```text
内置默认值  <  .ukit 描述符  <  Config/DefaultGame.ini  <  显式 CLI 参数或 GUI 本次操作值
```

- 配置不得硬编码在源码中；使用可读、可版本化的配置文件，并让 GUI 与 CLI 共享同一套模型。
- 不得在项目配置中存储密钥、令牌或敏感个人信息；这些应由系统安全存储或运行时环境提供。

## 工程管理入口

- GUI 启动时自动打开上次的工程（记录见「界面状态」）。记录指向的工程不存在或打不开时，展示完整路径与失败原因，并把状态还原为「未打开工程」，由用户从菜单栏新建或手动打开；不静默清空记录，也不退到别的工程。
- GUI 必须提供创建工程、打开工程、最近工程和工程信息页面。
- CLI 至少提供等价的 `project create`、`project info`、`project validate`。
- 创建工程时校验工程名、目标目录和 `.ukit` 文件名；不在非空目录中静默覆盖已有文件。
- 打开工程时校验格式版本、必需目录和配置错误，并给出可操作的迁移或修复提示。工程层诊断码使用 `UKIT` 前缀。

## 兼容性

- 默认兼容旧工具涉及的 Android UE Saved 路径规则，但允许项目配置覆盖。
- 兼容旧数据输入时保留原始文件，不在解析阶段修改输入。
- 修改旧行为前，更新 `Doc/旧版Python性能检查工具功能分析.md` 或新增迁移说明，明确兼容性变化。
- 提升 `FormatVersion` 时必须同时提供迁移路径和明确的错误提示，不允许旧工程静默失败。

### SettingsVersion 1 → 2（不自动迁移）

v1 把平台字段平铺在 `[UnrealKit.ProjectSettings]` 下，并用 `Platform` 字段表示当前平台，因此一个工程只能配置一个平台。v2 改为每平台一节，多平台并存。

**不做自动迁移**：v1 的 `Platform=Win64` 说明 Android 侧字段从未被填写过，迁移只能凭猜测补全，而猜错的设备端路径会让采集拉到空目录却报告成功。打开 v1 工程时 `ProjectSettingsFormat` 会失败并在错误信息中给出改写模板，字段对应关系如下：

| v1 字段 | v2 位置 |
| --- | --- |
| `PackageName` | `[UnrealKit.Platform.Android] PackageName` |
| `Activity` | `[UnrealKit.Platform.Android] Activity` |
| `DeviceGameRootTemplate` | `[UnrealKit.Platform.Android] GameRootTemplate` |
| `DeviceSavedRootTemplate` | 已移除（由 `GameRootTemplate` + `Saved` 派生） |
| `AdbPath` | `[UnrealKit.Platform.Android] AdbPath` |
| `Win64Executable` | `[UnrealKit.Platform.Win64] Executable` |
| `Win64WorkingDirectory` | `[UnrealKit.Platform.Win64] WorkingDirectory` |
| `Platform` | 已移除（由所选设备决定） |

改写时只保留本工程实际会跑的平台节，其余字段位置不变。既有 `Content/` 归档不受影响：归档目录早已按平台分区。
